IdePix S2 MSI plugin - Command Line Description

Command Line Description

Since the IdePix processor makes use of the SNAP graph processing framework, it can be used also as a command line tool. The graph processing is invoked by the command
  • ${SNAP-INSTALL-DIR}/bin/gpt
To obtain general help on the graph processing, use the command
  • ${SNAP-INSTALL-DIR}/bin/gpt -h
Specific help on the IdePix processor for a given instrument can be obtained with
  • ${SNAP-INSTALL-DIR}/bin/gpt <operator-name> -h
so we have here for S2 MSI:
  • ${SNAP-INSTALL-DIR}/bin/gpt Idepix.S2 -h
In this case, information on the usage and a list of all available parameters are given. The IdePix processor parameters can also be specified via a graph xml file. E.g., a possible graph xml file for S2 MSI could look like the following. (Note that in principle it is not necessary to explicitly set parameters if default values shall be used). 

    <graph id="IdepixS2MsiTest">
        <version>1.0</version>
        <node id="idepix">
            <operator>Idepix.S2</operator>
            <sources>
                <l1cProduct>${sourceProduct}</l1cProduct>
            </sources>
            <parameters>
                <computeCloudShadow>false</computeCloudShadow>
                <usePerCloudShadowMatching>true</usePerCloudShadowMatching>
                <includeCloudBufferForShadow>false</includeCloudBufferForShadow>
                <computeCloudBuffer>true</computeCloudBuffer>
                <cloudBufferWidth>2</cloudBufferWidth>
            </parameters>
        </node>
    </graph>
This graph can be invoked by the following call on the command line: 
    ${SNAP-INSTALL-DIR}/bin/gpt <graph-file.xml> -SsourceProduct=<path-to-source-file>

Performance settings

IdePix reports the effective in-memory tile-cache capacity, maximum Java heap, tile-scheduler thread count and available processors at startup. Non-blocking advice is logged for disabled or unusually small caches during cloud-shadow processing, insufficient heap headroom, or CPU oversubscription. These messages do not change settings. In Desktop they appear in the application log, not in a modal dialog. The low-cache thresholds are heuristics for large scenes, not minimum requirements: smaller subsets may work well with smaller caches.

Per-stage and per-tile timing reports are developer diagnostics and are disabled by default. To keep ordinary runs quiet, do not set -Dsnap.idepix.s2msi.cloudshadow.profile=true in gpt.vmoptions (or its -J-prefixed equivalent in Desktop configuration). The benchmark script reports one total elapsed duration per completed product. Developer profiling requires the opt-in property (or the script's -ProfileCloudShadow switch) and Java logging at FINE level; measurements and routine internal stage messages are not emitted at normal INFO level. SNAP's own progress and warnings are unaffected.

GPT: prefer explicit settings for each run

gpt Idepix.S2 -Sl1cProduct=input.dim -PcomputeCloudShadow=true -c 8G -q 16 -t output.dim

-c sets the tile-cache capacity (here 8 GiB); -q sets the number of SNAP tile-scheduler threads. These are GPT options, not IdePix algorithm parameters, and are also available when running a graph. Record them with benchmark results. IdePix's internal flag-read worker limit is reported separately; it currently uses the snap.parallelism JVM property (or available processors if unset), so -q alone does not control every internal worker.

A 4 GiB cache performed well for tested 20 m products; an 8 GiB cache substantially improved a tested full-scene 10 m run on a 32 GB-class, 16-logical-processor PC with a 21 GiB maximum heap. These are examples, not universal optimal settings. Use fewer threads and smaller per-job heaps/caches when running several GPT processes concurrently. More threads are not always faster.

Persistent GPT configuration

On Windows, edit <SNAP installation>\bin\gpt.vmoptions, keeping one JVM option per line. Back up the file first and edit existing entries rather than duplicating them. For example:

-Xmx21G
-Dsnap.jai.defaultTileCacheSize=8192M
-Dsnap.parallelism=16

Do not use the Desktop -J prefix in this file. Start a new GPT process after editing. Explicit -c and -q are the clearest way to select and record GPT's effective tile-cache and tile-scheduler settings; check the startup summary rather than assuming configuration files or saved preferences took effect. The maximum heap is controlled by -Xmx, not -c. Large -Xms values are unnecessary and can cause startup failures when Windows memory commit/page-file capacity is exhausted.

SNAP Desktop configuration

Use Tools > Options > Performance to adjust Cache Size (MB) and Number of Threads. For 8 GiB, enter 8192 in the cache-size field. Cache Path is a disk-cache directory; it is not the in-memory tile-cache capacity. Apply the settings and check IdePix's startup summary.

Alternatively, back up <SNAP installation>\etc\snap.conf and append these example options inside the existing quoted default_options value:

-J-Dsnap.jai.defaultTileCacheSize=8192M -J-Dsnap.parallelism=16

Leave the other launcher options intact, avoid duplicate entries, and restart Desktop. Desktop preferences can override launcher defaults; the reported effective settings are authoritative. Desktop heap settings use -J-Xmx in snap.conf, whereas gpt.vmoptions affects GPT, not Desktop. Installation updates may replace these files; check settings afterwards.

Memory and benchmark precautions

The tile cache occupies part of the Java heap; it is not additional RAM. Leave substantial heap space for source bands, operators and temporary arrays, and physical RAM for native libraries, the operating system, other applications and concurrent jobs. Do not copy the example heap/cache values onto a smaller machine. Close unused products before benchmarking. Warm the DEM cache first; downloads and remote errors can distort execution times. A 20 m input is the recommended practical starting point; 10 m contains four times as many pixels and can cost substantially more.

Changing SNAP's global tile size is not recommended as an IdePix tuning step: IdePix defines its own internal processing layout. Consult the processor description for algorithm parameters. Performance settings do not change the intended classification methodology.

IdePix S2 MSI Algorithm Specification

Algorithm Description

Overview

Sentinel-2 MSI IdePix performs mono-temporal pixel identification and classification for Sentinel-2 MSI Level-1C products. IdePix stands for Identification of Pixel Properties. The processor identifies atmospheric and surface conditions that may affect subsequent processing, such as cloud screening, atmospheric correction, land-surface analysis, or time-series generation.

The processor analyses top-of-atmosphere (TOA) reflectances together with scene geometry and, where required, auxiliary elevation information. It produces a bit-coded pixel classification containing cloud, cirrus, cloud-shadow, mountain-shadow, snow/ice, land/water, brightness, and related quality flags. The classification is not intended as a thematic land-cover product; it provides information that helps users decide whether a pixel is suitable for a particular application.

Input Product and Preprocessing

Sentinel-2 MSI IdePix requires a Sentinel-2 MSI Level-1C product that has first been prepared with SNAP's S2 Resampling tool, available under Optical > Geometric > S2 Resampling.

The input product must be resampled to a common spatial resolution of 10 m, 20 m, or 60 m. Resampling places the MSI bands required by IdePix on a common pixel grid and provides the input representation expected by the processor.

A 20 m input product is recommended for most applications. It offers a practical balance between spatial detail, classification quality, memory demand, and processing time. A 10 m input can provide more detailed classification masks, but is substantially more computationally demanding, particularly when cloud-shadow detection is enabled. A 60 m input reduces processing cost, but produces correspondingly coarser classification and shadow masks.

The resampled Level-1C product supplies the TOA reflectance bands, acquisition metadata, and solar and viewing geometry used by the algorithm. Depending on the selected options, IdePix also uses a digital elevation model (DEM) to derive elevation and terrain-shadow information.

Pixel Classification

The core classification evaluates spectral properties for each pixel. It combines information on brightness, whiteness, spectral shape and slope, normalized-difference indices, cirrus-sensitive spectral information, and land/water-related characteristics. These tests are combined to distinguish clear-sky, cloud, snow/ice, bright-surface, land, and water conditions.

Water-droplet clouds are provided at two confidence levels:

  • IDEPIX_CLOUD_SURE identifies pixels classified as opaque cloud with high confidence.
  • IDEPIX_CLOUD_AMBIGUOUS identifies semi-transparent clouds or pixels for which the cloud decision is uncertain.
  • IDEPIX_CLOUD is the combined cloud flag and is set when either IDEPIX_CLOUD_SURE or IDEPIX_CLOUD_AMBIGUOUS is set.

Cirrus clouds are identified separately:

  • IDEPIX_CIRRUS_SURE identifies cirrus clouds detected with high confidence.
  • IDEPIX_CIRRUS_AMBIGUOUS identifies uncertain cirrus detections.

Additional flags identify bright and white surfaces. These flags are useful because some bright land surfaces, urban materials, sand, snow, and ice can resemble clouds in individual spectral tests. The processor further provides flags for snow/ice, land, water, coastline, clear land, and clear water.

Cloud Buffer

Cloud boundaries are uncertain because clouds may be smaller than a pixel, semi-transparent, or displaced relative to the ground due to viewing geometry. IdePix can therefore optionally create a cloud buffer around detected cloud pixels.

The buffer is written to the IDEPIX_CLOUD_BUFFER flag. It marks otherwise clear pixels surrounding detected clouds and can be used as a conservative exclusion zone for applications that are sensitive to cloud-edge contamination. The buffer width is configurable as a Manhattan radius in pixels: it uses a diamond-shaped rather than square structuring element. Users can also choose whether ambiguous cloud pixels contribute to the cloud buffer.

The cloud buffer is an advisory quality flag. A buffered pixel is not necessarily cloudy, but lies close to a pixel identified as cloud.

Cloud-Shadow Detection

Cloud-shadow detection is optional and is disabled by default. When enabled, the cloud-shadow algorithm combines geometric and spectral information.

First, cloud pixels are displaced in the expected shadow direction using the solar and viewing geometry. Both sure and ambiguous cloud classifications contribute to this step. The cloud-shadow workflow operates on a 60 m working grid, where the required cloud flags and supporting reflectance information are prepared for shadow analysis. Flag values are conservatively combined during this preparation, while continuous supporting bands are averaged.

Second, the algorithm searches within the potential-shadow region for spectrally dark areas that are consistent with cloud shadow. Spatial clustering groups candidate shadow pixels. The geometrically projected cloud-shadow region and the spectrally detected dark clusters are then combined to derive the final IDEPIX_CLOUD_SHADOW flag. A scene-wide offset is determined first; by default, connected cloud objects are subsequently matched locally around that offset, which can improve the position of shadows from clouds at different heights.

Optionally, Include cloud buffer in cloud-shadow detection also treats cloud-buffer pixels as shadow-casting objects. This creates a more conservative result and can substantially increase processing time. The final cloud-shadow mask is returned to the input grid and receives a diamond-shaped safety dilation with Manhattan radii of four pixels at 10 m, two pixels at 20 m, and one pixel at 60 m. Potential-shadow and clustered-shadow masks are retained only as internal workflow information and are not written to the IdePix classification flags.

Cloud-shadow detection is more computationally demanding than the basic pixel classification. A 20 m resampled input is generally recommended for routine processing. A 10 m input should be used where the additional spatial detail is required and sufficient processing resources are available.

The cloud-shadow result is a quality mask and should be interpreted accordingly. Omissions can occur where shadows are weak, obscured, or spectrally similar to their surroundings. Commission errors are possible over naturally dark surfaces, terrain shadows, water, and complex land-cover patterns.

Mountain-Shadow Detection

Mountain shadows are derived independently from cloud shadows. When enabled, IdePix performs a terrain-cast-shadow calculation on the input grid. It traces the solar direction through the DEM using a directional terrain-envelope method and identifies pixels whose direct solar illumination is blocked by higher terrain. This is a cast-shadow calculation, not a local slope or hillshade test.

To represent shadows cast into the scene by terrain just outside its boundary, the calculation reads a fixed 5 km margin from the selected DEM. Solar geometry is represented by the scene-centre solar zenith and azimuth. The default DEM is Copernicus 30m Global DEM; users should select a DEM with suitable coverage and resolution for the scene, including the 5 km margin. The result is written to IDEPIX_MOUNTAIN_SHADOW. Its reliability depends on the quality, resolution, coverage, and geolocation of the selected DEM. It represents terrain-cast shadow and should not be confused with cloud shadow.

Output Product

The classification result is written to the bit-coded band pixel_classif_flags. Multiple flags can be set for a single pixel; the flags are not mutually exclusive. For example, a pixel may be classified as water and cloud ambiguous, or as land and bright.

The principal output flags are:

  • IDEPIX_INVALID
  • IDEPIX_CLOUD, IDEPIX_CLOUD_SURE, IDEPIX_CLOUD_AMBIGUOUS
  • IDEPIX_CIRRUS_SURE, IDEPIX_CIRRUS_AMBIGUOUS
  • IDEPIX_CLOUD_BUFFER
  • IDEPIX_CLOUD_SHADOW
  • IDEPIX_MOUNTAIN_SHADOW
  • IDEPIX_SNOW_ICE
  • IDEPIX_BRIGHT, IDEPIX_WHITE, IDEPIX_BRIGHTWHITE
  • IDEPIX_LAND, IDEPIX_WATER, IDEPIX_COASTLINE
  • IDEPIX_CLEAR_LAND, IDEPIX_CLEAR_WATER

TOA reflectances are copied to the target product by default. Optionally, the processor can write diagnostic feature values, such as brightness, whiteness, normalized-difference indices, and selected spectral-test values. These additional bands are primarily intended for algorithm diagnosis, validation, and scientific analysis.

Performance and Processing Settings

Cloud-shadow detection, terrain-cast shadow detection, and 10 m inputs can require substantially more processing time and memory than classification alone. A 20 m resampled input is the recommended default for routine cloud- and terrain-shadow processing. Performance settings are SNAP/GPT runtime settings; they are not IdePix operator parameters and therefore apply to the complete processing run.

For command-line processing, use GPT's -q option to set the number of processing threads and -c to set the tile-cache size. For example: 

gpt IdePix.S2 -Sl1cProduct=<input-product> -t <output-product> -q 6 -c 4G

The values must be selected for the available CPU cores and memory. Start conservatively, leave memory for the operating system and other applications, and keep the tile cache comfortably below SNAP's configured Java maximum heap. A larger cache can avoid repeated tile reads; allocating too much memory can instead cause paging or a Java out-of-memory failure. The default cache may be too small for large Sentinel-2 processing workloads.

In SNAP Desktop, open Tools > Options > Performance to set Cache Size (MB) and Number of Threads. These are application-wide settings rather than controls in the IdePix processing dialog. The same page also shows the tile size selected by SNAP; changes should be made deliberately and tested on representative scenes.

Limitations and Recommended Use

IdePix is a mono-temporal method: it uses information from the individual input scene and does not use observations from earlier or later acquisitions. Results can therefore be affected by unusual surface reflectance, cloud type and height, illumination and viewing geometry, snow, terrain, coastal adjacency, and atmospheric conditions.

The cloud, cloud-shadow, and mountain-shadow flags should be interpreted as quality indicators, not as absolute truth. Users should select flags according to the required balance between conservative masking and data retention, and should validate results for new regions, seasons, or surface types.
